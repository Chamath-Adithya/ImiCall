# How ImiCall is maintained

Chamath Adithya is the project founder and current maintainer. The maintainer sets release scope, reviews changes and makes final decisions about the official project. This is project governance, not a transfer of contributors’ copyright.

## Decisions

Small fixes can start as a pull request. For protocol, storage, permissions, licensing or large dependency changes, explain the problem and tradeoffs in an issue first. Security-sensitive details belong in a private report. Decisions should be explained in the issue or PR so future contributors can understand them.

Reviews consider user benefit, privacy, accessibility, maintenance cost and performance on modest devices. Passing tests is necessary but does not guarantee acceptance. No response-time or release-date promise is made.

## Credit and ownership

Authors retain copyright in their own contributions. The maintainer retains copyright in original material he owns. Third-party notices remain intact. A future contributor sign-off certifies contribution rights; it is not copyright assignment or blanket permission for proprietary relicensing.

ImiCall’s official name, logo, domains and release channels are separate from source-code license rights; see TRADEMARKS.md. Forking rights are governed by the applicable code license.

## Growing the project

Repeated, thoughtful contributions can lead to review or maintenance responsibility. Repository access is granted deliberately, with least privilege. Community participation does not create employment, ownership shares or a revenue entitlement unless a separate agreement says so.
